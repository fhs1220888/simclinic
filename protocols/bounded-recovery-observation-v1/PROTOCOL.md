# 有限恢复：自然故障观测与新保留评估 v1

本文件冻结研究设计，不启动模型、Docker、求解或采样，也不等同于执行环境已经冻结。机器计划见 [protocol.json](protocol.json)，任务输入和原验收见 `definitions/`；计划状态为 `frozen_design_only`、`execution_ready=false`、`execution_authorized=false`。执行前缺口见末节。本轮生成的参考字典是未运行输入，不是 CFD 验证证据。

## 问题、范围与已有依据

研究问题是：在固定工作流的未注入运行中，明确采样输出缺失和满足有限恢复资格的情况出现多少；启用候选后，完整任务成功率、恢复代价与全部消耗如何变化。自然观测和明确注入各自形成结果表，不能合并成自然收益。

限定 Foam-Agent v2.1.0、Foundation 10 / simpleFoam、稳态不可压缩单相层流 Couette、本地串行。已有[交付](../../patches/simclinic-bounded-sampling-recovery/README.md)的 manifest SHA 为 `9f1e77465663e88f61cbafd7dbdb045bbe2d89ad4c128ed750c4ce34c8971b72`；原评估冻结 SHA 为 `5fe1c82fe06adde350c10362dbe7af080cff010327a0752b33803858217bd3f8`。已证明效果限于受控首次新采样输出丢失后的恢复。新协议不预先宣布自然收益、统计显著性、稳定节省或综合优化。

基线使用 `ContractReferenceCompletion`，候选使用 `RecoveringContractReferenceCompletion`，共有九文件 v3 输入评估器、模型、规划/输入生成/求解/U 渲染、检索语料、观测与验收。唯一行为差异仍为一次受限额外采样；共有观察器必须同时登记两组恢复资格，不能拿候选的 recovery decision 是否存在当资格判据。

自然与注入的全部任务、次数在观测前一并声明；注入阶段沿用同一预声明参数矩阵，只作另一个情景，不能声称再次提供一套全新任务独立性。四个保留任务一旦保留阶段开始，都转为该研究的已使用数据。观察中不得修改策略、阈值、模板、语料或参数；如果暴露新缺陷，保留原成绩，停止并另立版本，不能调好后补跑。

模型只获得当前任务声明和固定 C0 语料；预期参考输入仅供独立验收，不进入检索库，不提供已求解的保留结果、归档回复或图像。生成的 `Allrun` 和九文件数值契约原样核对。

## 冻结质量与恢复边界

所有任务使用长 1 m、高 0.1 m、厚 0.01 m、nu=0.001 m²/s、上下壁 Couette 边界、固定入口解析分布和零压强梯度。只改变预声明壁速与网格；不在运行中调参。

完整质量必须同时满足：求解退出零且观测到 End；原 SIMPLE 标记或两份可信正时间全场 U/p 的变化分别除以声明尺度不超过 `1e-7`；末步局部连续性误差 ≤`1e-7`；两条固定采样线所有 U 分量相对 L2 误差 ≤`0.02`；两方向压力斜率范数除以预声明非零尺度 ≤`0.03`；九文件 v3 输入通过；当前身份的原生 U PNG 符合要求。原 SIMPLE 标记继续单列，包括 false。任何原准则未知或不满足都不能成功；采样通过不是完整质量通过。

恢复仅允许 typed `sampling_missing_output`：首次 sample 已启动，exit 0、无 fatal/未知日志、失败 assessment 与事件一致；当前 run/input 和生成时可信字节仍核验通过。从全新可信工作区额外采样一次，保存首次失败和全部额外消耗。恢复不重新求解、不改物理/数值设置或原验收。fatal、timeout、非零退出、旧/未知身份、空/歧义/越界输出不可包装为可恢复成功；第二次仍失败或末端身份变化时诚实终止。

原有共享 reviewer 最多两轮、仅处理原任务内允许的输入问题；每轮求解、模型请求与失败均记录。它不因采样缺失重新求解，不因未达稳态延长 endTime、修改初值/离散设置或放宽阈值。既有 reviewer 如不能保证此边界，应在执行前拒绝启动，而不是把越界行为计入候选收益。

## 自然观测的分母和证据

自然阶段完全禁用注入器，不能为了等到故障删文件、制造资源紧张、缩短超时或更换环境。正常和失败都逐次完整归档；错误是观测，不能只保存“值得诊断”的运行。

| 符号 | 定义（每组单列） |
| --- | --- |
| N | 所有已启动完整任务，包含规划/输入/求解失败、未到达采样、中断和未知 |
| M | 到达第一次 sample 函数调用尝试的任务数，包括明确 launch failure；每任务只计一次，额外 sample 不增加分母 |
| F | 首次已确认 `sampling_missing_output`，且 exit 0 与无 fatal 的日志可核验 |
| E | F 中另经共有观察器确认当前 run/input/可信字节和有限恢复边界均满足者 |
| S | 原完整质量验收成功的任务数 |
| A | 候选实际启动额外 sampler 的任务数 |
| R_sample | A 中第二次 sampler 证据通过的任务数 |
| R_full | E 中候选最终原完整质量通过的任务数 |

报告自然 `F/M`、`E/M`、`E/N`，并列 N、M、F、E 的原始计数。未到达 sample 的任务、已确认 launch failure、launch 状态未知、首次结果未知、明确不可恢复原因和资格未知各自列出；不能把缺失记录当“没有故障”。这些比例的频率范围是首次采样调用尝试，不是假定每次都成功启动的 sampler。实际启动计数及未知启动单列；旧 `execution_started=true` 在 subprocess 调用前设置，不能单独作为启动证据，新观察器需保存调用入口及实际进程/PID/返回或启动失败证据。

令 U_F 为 M 中无法判定首次是否属于明确缺失的数量，U_E 为已确认 F 中恢复资格未知的数量，两者互斥。F/M 只是已证实比例；已知首次结果子集为 `F/(M-U_F)`，未知可能范围为 `[F/M, (F+U_F)/M]`；资格可能范围为 `[E/M, (E+U_F+U_E)/M]`。按全部启动任务的资格范围可除以 N。零分母为 null。这些是未知观测的最宽识别范围，不是置信区间或总体推断，不将不确定项填零。

资格判断必须在首次失败后、任何候选恢复之前登记：以调用者当前身份、生成时 manifest、原始结果与输入哈希、门禁日志/输出列表为证据，记录 `eligible=true/false/null` 和原因。基线也执行相同只读核验；不额外采样、不改变失败。候选恢复之后的成功 decision 不能追认首次资格；离线只能依据当时记录核验，不用目录后来状态补贴身份。

如 E=0，报告“本观察窗没有确认可恢复机会，自然恢复收益不可评”；不能据此宣布自然故障不存在或候选无收益。该 pilot 是固定参数分布下的探索性描述，不是统计功效充分的显著性试验，也不是部署环境总体频率估计。

## 注入规则与可比性

只有干预前原完整采样门禁能通过，才可注入：第一次真实 sampler 进程成功，日志 UTF-8、无致命/未知状态，当前工作区/身份和原始字节可信；`profile.xy` 与 `pressure.xy` 均恰好一个当次新生成、安全非空输出，并由原测量读取器完成两条线的格式/点位解析。这里不要求参考误差已达标，物理质量仍由原验收决定。随后归档 profile 原字节、SHA、argv、exit、两份输出的核验/可解析证据、工作区 manifest 和 `natural_failure=false` 的 intervention，再删除 profile。两组使用相同规则；不改求解结果、pressure、输入或当前身份，第二次不注入。

若首进程自然失败、任何必需输出已缺失/无效、日志或身份未知、原读取器不能解析，不能制造一个看似成功的注入。标为 `injection_not_applied` 并保留真实失败与全部消耗；不能补跑。出现不能施加预声明干预时，以 `noncomparable_intervention` 停止 I 阶段并报告已开始前缀，不能继续凑齐预期注入次数。自然故障在注入阶段偶然出现仍属于“注入阶段、干预未施加”的单列观测，不混入 N 的频率分母。旧仅检查 profile 的 injector 不能直接沿用。

完成 I 后报告全部已启动任务的成功率，并另列实际成功施加干预的覆盖率、条件恢复和失败；只分析成功施加的子集不能代替全任务结果。

## 收益与消耗报告

主结果是每阶段每组 `S/N`，及候选减基线的百分点差。同参数与重复形成受控配对，但两组自然故障不保证同步；某次候选恢复成功不能直接等同一次可观察的反事实净收益。自然与注入各自解释，不输出自动“优化已证明”标志。

候选另报 `A/E`、`R_sample/A`、`R_full/E`，未知资格单列。采样恢复与完整恢复分开，原五项体检的错误完成、无效重复重试、证据不足和不适用分别保留。允许一次尝试不豁免持续失败的无效重试发现。

全部已启动任务的 token、模型调用、求解次数/步骤耗时、采样次数/步骤耗时、工作流墙钟、复制与核验开销、证据量全部计入，包括失败、中断和额外恢复。未知 token/费用维持 null，已知部分仅为下界。主表给总量、每启动任务消耗及 `全部消耗/完整成功任务数`；零成功或相关总消耗未知时单位成功成本为 null/未定义。

恢复成本包括首次失败和额外 sample 的各自 `elapsed_seconds`、恢复整个分支的墙钟和最终完整工作流。sample 字段包含函数内核验、Docker 执行/清理、日志解析及证据处理，不能称纯进程 CPU 时间。新观察器另记录恢复分支开始/结束，避免把副本构建和最后身份核验漏出恢复代价；记录器开销两组共有。

每组提供全部运行的分布、任务分层和失败类别表。仅双方完整质量通过的配对耗时/token 可作副表，注明成功条件选择偏差，不能由该表宣布总体或稳定节省。此 pilot 不预声明显著性检验或总体优化；需要新的功效、代表性和更大观测协议才能作这些结论。

## 次数、预算和停止规则

本设计提议 76 次运行，需另行授权执行。token 规划总边界 22,000,000：D 1,500,000，N 13,500,000，I 7,000,000；阶段预算不借用。每次运行前至少保留 450,000 余量，每次模型请求前检查已知消耗，单 run 最多 32 次请求，单请求超时 240 秒；求解超时 180 秒，sample 超时 120 秒。共享 reviewer 最多两轮，模型渲染回退关闭。时间规划为 D 30 分钟、N 4 小时、I 90 分钟，总 6 小时。

450,000 余量是启动准入，已知消耗边界与时间边界是检查后停止边界，不保证一条在途模型请求不超额；无逐请求最大计费承诺时不得写成硬费用上限。越界后记录实际全部消耗并停止后续任务，不能回写成预算内。费用未知，不以 token 推算已知账单金额。

参照上一批每 28 次的 476 调用、6,437,556 token 和约 73.9 分钟，76 次的线性规划参考约 1,292 调用、1,747 万 token、3.3 小时，另加新观察器/归档核验；不是性能、费用或完成时间保证。新故障、后端延迟和预算提前停止均可能改变实际量。

每次运行前检查冻结哈希、序列、当前环境、预算和保护是否有效。完整记录且身份可信的诚实任务失败或采样超时/未知退出继续计分；不能只因 quality=false、工具 outcome=unknown、tools_complete=false 或子进程非零就当采集/基础设施失败。采样超时保存完整部分日志、超时及退出未知证据，是任务观测；证据采集缺失才是采集失败。D 任一质量失败、错误完成声明、恢复策略越界、模型后端失败/超时、未知用量、采集不完整、身份/来源不可核验、可检测环境漂移、保护失效、预算/时间余量不足时停止；注入不可比按上节停止 I。

所有已开始尝试进入日志和消耗。停止报告 started/planned、完成覆盖、未启动 ID、停止原因、已知消耗下界与未知量；未启动任务不虚构为失败。不续跑、不替换失败、不选择性重跑，不为得到自然故障延长次数，不因观察到收益提前结束。

## 归档与执行前缺口

新执行批次必须另建目录，并保存执行 freeze、协议 SHA、环境/源码/native/语料/任务哈希、完整序列、逐次记录、原始模型请求与回复/metadata、所有输入快照、求解状态/日志、U 图、首次 sample 日志/assessment、共有资格 assessment、恢复 decision/第二次证据、intervention 原字节、完成声明/原验收、五项审计、原评分、全部消耗和停止记录。原失败与旧两轮输入评估器成绩不回写。

当前执行缺口：

1. 新驱动需区分 `honest_task_failure`、`backend_failure`、`infrastructure_failure`、`collection_failure` 和未知。旧 coordinator 的非零退出笼统归基础设施规则不能直接沿用。
2. 共有首次失败后的资格观察器、首次调用与真实启动证据、自然模式禁注入、干预前完整原门禁资格、恢复分支完整计时、分母/未知值评分器尚未实现并验证。软件模拟与已知归档回归不能声称新自然观测。
3. 新驱动与观察器完成后，在新执行 freeze 中核对实际环境、源码和所有任务字节；设计中的 environment_basis 只是旧环境依据。
4. 新 C0 四项开发必须在该执行 freeze 内通过后才能进入保留；本次未运行这些检查。
5. 运行 76 次的成本范围需单独授权；本协议不授权启动。没有授权时只推进离线实现和验证。

以上条件未齐备，设计核验工具仍返回 `execution_ready=false`。设计完整性核验命令：

```bash
python3 scripts/check_recovery_observation_protocol.py --protocol protocols/bounded-recovery-observation-v1
```

执行前另做库存重扫并核对新任务仍未被其他工作使用。若库存/源码发生变化，保留此设计版本，另建协议版本和执行冻结，不改已经执行的数据。
