# 四个任务的通过标准

材料版本：20261012，配套同日首版交付；原T1–T4技术标准与H0–H3帮助判定沿用。当前实际试用继续暂缓，本次仅同步材料，不产生用户通过结论。

供组织者核验。所有判定必须来自用户本次操作与输出；维护者先前通过的回执只证明交付基线，不代替独立用户结果。用户可以查看随包文档中的预期值，但必须指出自己本次证据和做出正确解释。

## 前提与证据

记录使用的交付版本/文件、系统、Python、Git/Bash以及是否有维护者仓库或旧库存。预期使用原 `0.11.0+collect1` 本地wheel、独立新venv、新before/after目录、已有no-log-failure。未确认前提时单独标注，不把其他任务或其他平台的结果混进本范围。

| 任务 | 技术通过标准 | 用户理解与证据 |
| --- | --- | --- |
| T1 安装 | 安装命令退出0；`simclinic --version`为0.11.0+collect1；执行包来自用户新venv，不依赖维护者仓库 | 用户能指出安装目录和实际使用的命令；仅复制旧成功回执不算通过 |
| T2 发现问题 | 本次基线collect及报告产出完整；摘要实际退出7、原执行成功结论true；`error_continuation=finding` | 能指出本次report里的check_id和事件位置，以及进程实际失败却被报告成功的矛盾；“有finding”不够 |
| T3 应用补丁 | 本次after/patch-application.json的四条git apply --check/apply命令均退出0，`applied_snapshot_matches_existing_candidate=true`；patched采集完成 | 能找到回执和after/patch-sandbox，说明修改在新源码沙箱；没有改写自己的其他Agent或原包 |
| T4 复测 | 本次两版实际退出均7，成功结论true→false；`error_continuation`为finding→not_applicable；compare.comparable=true；新run ID不同、input_version相同、声明范围coverage完整 | 能结合两版摘要/报告/record解释“修正错误成功报告，失败任务仍失败”；complete表示限定采集完成，不表示任务验收成功 |

T4同时检查Shell输入的执行验收仍未满足，没有伪造数值/参考完成。不要要求该控制例finding全部为0或任务变成功。`collect`退出0与Allrun实际退出7并不矛盾；前者是采集命令，后者是被采集任务。

`audit --fail-on-finding`不是本轮必做命令；如果用户执行，基线退出1和补丁后退出0是预期，不将基线1算作安装故障。`showcase`成功或已有CFD报告通过都不能替代本轮分步任务的新记录。

## 独立完成如何认定

| 最终状态 | 条件 |
| --- | --- |
| 独立通过 | T1–T4技术与解释均通过，证据可核验；全程H0 |
| 辅助完成 | 最终四项通过，但出现H1/H2/H3或使用任务相关额外外部帮助；保留帮助前的卡点 |
| 未完成 | 已尝试，但至少一项明确未通过、失败或放弃 |
| 证据不足无法判定 | 声称完成但缺输出，或无法区分本次与旧记录；不补成通过 |
| 未开始 | 没有实际尝试；不能算失败，也不能算完成 |

缺依赖、看不懂报告或需真人解释都是要记录的试用发现。参考时间用于了解摩擦，不设“超过45分钟必失败”的规则。满意度与实际通过分开记录。

## 首批结果与问题优先级

首批验收目标为3名符合前提的用户全部独立通过。报告实际开始人数以及独立通过/辅助完成/未完成/无法判定/未开始的原始数量；不要把辅助完成混进独立通过或删除卡住的尝试。当前尚无用户数据，首批独立可用性仍待证实。

| 优先级 | 例子 | 下一步仅列问题 |
| --- | --- | --- |
| P0 阻断或错误结论 | 支持范围内无法安装/应用/比较、错误回执、复测身份或文件不一致 | 记录可复现命令、环境、原日志及影响任务 |

| P2 可完成但摩擦明显 | 术语、路径或提示令人反复查找 | 记录查找次数/耗时及具体文字位置 |
