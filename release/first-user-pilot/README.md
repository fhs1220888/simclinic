# 首批独立用户试用准备

此处为待恢复的任务资料，当前可公开产品入口见[同步说明](../../releases/20261012/PUBLICATION.md)。完整本地封版ZIP尚未公开上传。

资料日期：2026-10-12。交付版本固定为 `0.11.0+collect1`，产品基线为 `simclinic-first-release-trial-20261012.zip`，外层试用材料包为 `simclinic-first-user-pilot-20261012.zip`。此套资料仅同步已有功能的试用安排；用户收集、联系与实际试用继续暂缓，T01–T03未分配、未开始，尚无独立用户结果。以下流程供后续决定恢复时使用，本次没有发送资料或运行案例、实验。许可决定继续暂缓。

建议先准备3个名额，编号T01–T03；这是首批安排，不是统计结论。目标用户能使用终端、使用支持范围内的POSIX环境，之前没有参与SimClinic开发，也没有维护者仓库或历史库存；Python3.9+及Git/Bash的准备情况在T1记录，缺依赖不能作为事后剔除失败的理由。首批优先使用已验证的macOS环境；其他POSIX环境单独标注平台状态，不据一次成功扩展平台承诺。依赖准备时间与操作时间分别记录，参考预留30–45分钟，不把超时单独判为失败。

## 给用户什么

统一资料包一次解压后，`product/`就是20261012首版交付的全部170个文件，内容与对应产品ZIP逐文件一致，包括修正后的INSTALL及SHA256SUMS。无需重新组合历史交付；产品内20261011运行回执和STATUS日期是历史验收/封包快照，不是本次新运行结果。当前暂停状态以本外层说明及PREPARATION.json为准。

1. 让用户从[任务卡](PARTICIPANT.md)开始，按其中链接使用 `product/README.md`。
2. 分配一个编号，填写对应 `feedback/T01.md`、`T02.md` 或 `T03.md`；空白模板在[反馈表](FEEDBACK-TEMPLATE.md)。
3. 用户保留本次产生的before/after、comparison和反馈文件，约定本地交接方式后由组织者收集。没有自动发送或上传。

本轮必做“安装→基线采集与问题定位→补丁版采集→比较复测”，使用同一个已有Shell失败例。默认不运行showcase、Docker或Foundation10求解；showcase已有能力仍随产品提供。真实通道证据仅供查看，不要求重新求解或申请模型账号。

## 组织者如何观察

开始前只确认编号、环境、拿到资料和新工作目录。用户可以自由阅读所有交付文档，包括故障排查；不需要背命令或猜隐藏答案。让用户实际产出新记录，并用自己的话解释证据。

除非用户明确求助，先不代操作或给下一条命令。卡住时记录所在任务、原命令、错误、已查的文档和原话；之后可以帮助，但必须记录首次求助发生在何处以及帮助内容。不要把获得帮助后的成功倒填成独立完成。明显无法继续时保留原失败状态，用户可以结束或接受帮助。

| 帮助等级 | 判定 |
| --- | --- |
| H0 | 仅使用随包文档、命令自身帮助及自己的终端，无真人针对任务/依赖的帮助 |
| H1 | 外部资料提供一般依赖指引，或真人解释依赖、提示文档位置、解释任务含义 |
| H2 | 真人提供具体命令、定位错误或解释本次结果 |
| H3 | 真人代安装、代执行、远程操作或替用户填写关键结论 |

每个任务记录等级和时间；整体采用最高等级。任务卡本身属于文档，不算真人帮助。其他来源的额外教程、搜索或AI帮助也要记录；涉及解决本次任务的具体帮助按H2处理。用户日常终端经验不算帮助。

## 判定与回收

按[通过标准](ACCEPTANCE.md)逐项核验，填[首批跟踪表](TRACKER.md)。结果分为独立通过、辅助完成、未完成、证据不足无法判定、未开始；不能只用退出0、finding减少或满意度决定。

首批目标是3名符合前提的独立用户全部H0完成四个任务并提交可核验证据。若没有达到，保留逐人的阻塞和帮助记录，列出影响闭环的文档/交付问题。人数不足时明确报告未达到目标，不推定完成。平台不符合前提的尝试单独记录，不隐去失败或事后更改资格。

汇总至少写出：计划人数、符合前提人数、实际开始人数、各结果人数、每步卡点、首次求助位置、缺依赖与操作耗时，以及需要优先收敛的问题。不用3人试用推断总体成功率、优化收益或跨平台稳定性。本次只准备材料；实际试用与后续修正文档另按结果推进。
