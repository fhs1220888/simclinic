## 先冻结共同采集契约

0.6 已规范化限定路径的 checkMesh 门禁、实际路由、reviewer 处理/改写计划、跨 run/input 的显式重试关系及注册 completion 节点；真实正常/恢复/耗尽场景支持该范围的覆盖声明，见 [采集结果](observed-workflow.md)。自由文本导入及未注册外部行为仍无此完整保证。缺少事件的运行按证据缺失统计，不能归入成功。

冻结两套源码、模型、检索语料、依赖和镜像 SHA-256。基线与候选使用同一个真实模型适配器、容器资源和外部观测层；只有预先声明的流程/工具改进不同。先在开发样本验证共同运行层，不能因原后端无法启动而把环境失败计成候选优势。

共同任务验收与显式完成接口必须对双方一致；不能直接把旧版三项证据不足与新版零证据不足比较成优化效果。求解器错误恢复时跨输入关联要求显式 retry_of/session，保留所有失败尝试；候选改动清单和归档哈希在第一项保留任务运行前确定。

## 运行与统计

先在开发任务验证采集，再按已明确的模型预算开展小批次。建议每个保留任务各做 3 次基线和 3 次候选，共 18 次完整模型运行；交错顺序，固定模型版本与推理配置。供应商未提供可靠 seed 或后端快照时明确这一限制，不能声称完全可重复。

逐次保存真实执行、数值与参考验收、任务输入符合性、所请求的绘图字段、失败、错误完成声明、无效重试、证据缺失、求解耗时、整体耗时和实际 token。质量不达标的任务不能因拒绝旧结果就归为成功。成本仍保持 null，除非取得可核验账单口径。

自然模型运行与明确故障注入分别统计。旧结果、退出码和日志缺失的契约测试只证明指定路径的防线；不把注入场景频率当作真实业务失败率。

报告每组样本数、逐次值、失败比例、均值/中位数/范围。只有双方证据足够、质量门禁保持的样本才比较消耗；同时展示全部失败和缺失情况，避免只挑成功运行。小样本仅作探索，不宣称普遍或统计显著的优化。

完整运行目前每次约 17 次独立模型调用，usage 约 22–23 万 token，包含会话上下文开销。18 次批次约 400 万 usage token，仅用于估算预算，实际值以运行归档为准。
