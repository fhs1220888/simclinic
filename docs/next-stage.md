## 接入步骤与验收

1. **读取固定源码与真实归档**：确认 logger、工具接口、runner 状态机与 reviewer 输出；保存环境/Agent manifest。验收：可展示具体 commit 和一次真实运行的原始来源，不依赖合成样本猜测。
2. **结构化采集**：工具执行前创建新的 run ID，捕获输入 manifest/hash；执行后保存 exit_code、日志、outputs manifest 与时间/可用模型消耗。mesh/config 检查同时保存文本解析 outcome。输出归属在生成时登记，不能导入时补写当前身份。验收：不同输入与重复运行可以稳定区分。
3. **分层验收**：分别记录 execution（退出/结束/必要文件）、numerical（任务规定的稳态收敛、守恒等）和 reference（解析/公开参考偏差）。验收：程序结束但未收敛、数值达标但参考不符均不得等同成功。
4. **真实审计**：用 normalized adapter 导入以上证据，映射五类事件；真实采集中无法取得的字段继续 null/unknown。验收：正常、故障和证据缺失报告能回溯真实事件或原始文件。
